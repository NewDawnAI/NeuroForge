# It learns

Date: 2026-08-24
Follows: `why_it_does_not_learn_2026-08-24.md`

The brain now solves the phototaxis task, going from chance to sitting beside the
light. Getting there needed a learnable policy — and, more instructively, three
separate defects that each silently made the task unsolvable regardless of the
learning algorithm.

## Result

1,500 steps, three runs per condition, mean distance to the light on an 8-ring
(random walk ~2.0, standing on the light 0):

| | run means | overall | within-spread |
|---|---|---|---|
| fixed argmax | 2.18, 1.75, 2.48 | **2.139** | 0.73 |
| learned policy | 0.92, 0.98, 1.00 | **0.967** | **0.08** |

Effect **+1.172**, larger than the largest within-condition spread (0.733), with
**no overlap** between conditions: fixed ∈ [1.75, 2.48], learned ∈ [0.92, 1.00].

Final quarter: **0.711** learned against **2.178** fixed.

The learning curve appears in every run, each starting from uniform weights:

```
run1: 1.67 -> 0.60 -> 0.80 -> 0.60
run2: 1.67 -> 0.73 -> 0.87 -> 0.67
run3: 1.67 -> 0.67 -> 0.80 -> 0.87
```

The learned condition's spread collapsing to 0.08 is itself evidence: three runs
converging to the same behaviour despite the residual nondeterminism that leaves
the fixed policy scattered across 0.73.

## 1. The learnable policy

`PrefrontalCortex::makeDecisionLearned` replaces the hardcoded

```cpp
auto max_it = std::max_element(values.begin(), values.end());
```

with a softmax policy over a linear score, `score[a] = sum_f w[a][f] * x[f]`,
sampled at a temperature. `reinforcePolicy` applies REINFORCE:

```cpp
dw[a][f] += lr * reward * (1[a == chosen] - p[a]) * x[f];
```

That advantage term is the part that was missing entirely. Phase-4 eligibility
bumps every synapse of every spiking neuron by a flat amount, which records "was
active" rather than "was responsible"; this raises the chosen action and lowers
the others in proportion to how likely they already were, so credit lands on the
action actually taken.

Three deliberate choices: weights start at **zero**, so the opening policy is
uniform rather than arbitrarily biased and the first episodes are pure
exploration; actions are **sampled**, because an argmax over near-tied values is
effectively deterministic and a policy that never tries an alternative cannot
discover a better one; weights are **bounded**, because an unbounded linear score
saturates the softmax and the policy then stops exploring and cannot recover from
an unlucky early run.

## 2. Three defects that made the task unsolvable

None of these was a tuning problem. Each is provable from the code, and each
alone was sufficient to prevent learning.

**(a) A region mean cannot represent direction.** The observation encodes bearing
as a left/right imbalance, +0.35 on one half and -0.35 on the other.
`readRegionSignal` returns `average_activation` over all 64 neurons, and both
bearings give the **identical** mean — clamping is symmetric across halves and
does not break the tie either. The policy was bearing-blind by construction.

**(b) `processVisualInput` discarded 75% of the field.** It looped over
`layer_neurons_` writing `visual_input[i]` into neuron `i` of *every* layer.
`initializeLayers` splits 64 neurons into 4 layers of 16, so only the first 16
input values were ever read, replicated four times. Any reader splitting the
region's neurons to recover spatial structure saw the same values on both sides.
Now the input maps straight onto the region's neuron vector, keeping input index
and neuron index aligned; layers still share those neurons, so layer-wise
processing is unaffected.

**(c) The split was by row, not column.** The observation is a row-major 8x8
grid, so left/right is `i % 8 < 4`. Splitting the neuron vector at 32 separates
rows 0-3 from rows 4-7 — equal left and right field on both sides, difference
exactly zero. This was my own bug, introduced while fixing (a), and it produced
the same symptom as (a) and (b): a bearing feature pinned at the normaliser's
neutral 0.5.

Only after all three were fixed did the spatial channels vary at all, spanning
0.03 to 0.98 instead of sitting at 0.5.

## 3. A false positive, recorded

An intermediate 600-step run showed the learned policy improving 4/4 within runs
while the fixed policy degraded 4/4, and it was reported as a learning signal. It
was not. A 1,500-step run reversed it (fixed 1.656, learned 1.900).

The tell was in the data and was missed at first: all four `off` runs had a first
half of exactly **1.08** and all four `on` runs exactly **2.17**, identical to two
decimals across supposedly independent runs. That means the early trajectory was
deterministic and the four runs were one trajectory repeated, not four
confirmations. Repetition was read as consistency.

The result in section 1 does not share that flaw: the three learned runs diverge
after the opening quarter (0.60/0.73/0.67, then 0.80/0.87/0.80) and the
conditions separate with no overlap.

## 4. What this does and does not establish

**Does:** a reinforcement signal computed from the environment changes the
brain's behaviour in the direction the reward defines, reproducibly, with an
effect well outside run-to-run noise. The loop is closed end to end — sense,
decide, act, consequence, reward, update — and the update now changes what the
agent does.

**Does not:** that the *synaptic* machinery learns. The policy weights that moved
are in `PrefrontalCortex`, not in the connectome. Phase-4 reward-modulated
plasticity still fires (237,409 updates in an earlier run) and still has no
measurable behavioural effect, for the reason given previously: uniform
eligibility broadcasts reward to everything recently active. Making Phase-4
itself carry action-specific credit is a separate, harder problem.

So the honest framing is that a policy learner was added *alongside* the
biological substrate, not that the substrate learned.

## Verification

- Default path unchanged: 148,604 updates / 102 synapses.
- Anatomical determinism intact: Thalamus 0.6955 x 3.
- `--vision-demo` still works after the `processVisualInput` change: 583,653
  updates, 13,109 synapses.
- Full build: 106/106, 0 errors.
- Test sweep: 33 pass, 3 fail — the pre-existing baseline.

Note that fixing `processVisualInput` changed **both** arms, so the fixed-policy
baseline moved from 1.656 to 2.139. Comparisons are only valid within a single
observation regime; the numbers in section 1 are all from the fixed one.

## Next

   a policy layer bolted beside it. This is the real target.
2. **A harder task.** Phototaxis with a direct bearing cue is close to the
   simplest possible closed loop; the policy is linear and the state nearly fully

   `src/core`) is now small relative to this effect but still unlocated.
